# Fragment: technical exploration

Use for read-only repository understanding or architecture decisions.

1. Scope the question and map only the necessary code, tests, configuration and execution paths.
2. Trace a representative input to its result; cite repository symbols, paths and primary evidence.
3. Mark each material claim **observed**, **inferred**, or **unknown**. Say what evidence would resolve unknowns.
4. Compare the current design, a no-change option and viable alternatives using correctness, complexity, maintainability, performance, migration costs and reversibility.
5. Prefer primary documentation and source code for external claims; do not fabricate benchmarks or maintenance status.
6. Answer directly, state what to retain, and recommend the least complex supported choice.

Do not modify files. If an authorized implementation is subsequently needed, use repair.md for a defect; a new feature requires separate instructions.
